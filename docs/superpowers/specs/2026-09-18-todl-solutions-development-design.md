# TodlSolutionsDevelopment — Solution Explorer design

**Goal:** A new solution-level explorer + lifecycle service in `plexus-core`,
mirroring the Project Explorer architecture, driving TODL's headless solution
engine. devUI is the first consumer (replacing its current solution module);
Plexus adopts later.

**Architecture:** A new `plexus-core` module `todl-solutions-development` owns a
project-explorer-style `SolutionExplorerService` (its own `OpenSolution` tree,
lifecycle commands, mural `Capability` presentation). It drives the existing
TODL engine (`SolutionManagerService` / `SolutionViewService` / `SolutionSession`
/ `Domain`) directly — `plexus-core`'s `todl-runtime`-only floor is relaxed to
add `@pragmatic-tech-ai/todl`. App-specific seam impls (package source over IPC,
concrete project factories) stay app-side.

**Tech stack:** mural (ServiceBase, ObservableCollection, MuralBase, DataTemplate,
Capability, `.mu`), `@pragmatic-tech-ai/todl` (solution engine + Domain),
`@pragmatic-tech-ai/todl-runtime` (IStorage, Observable), electron-vite.

**Spec status:** design validated interactively (2026-09-18). No code until the
implementation plan is approved.

## Global constraints
- Interfaces + public methods **PascalCase**; VMs extend **Observable** (tree
  nodes may extend MuralBase to match `OpenProject`/`ProjectNode`); **enums** over
  string-literals; tests in `tests/` subfolders; no seam-bags (depend on real
  classes/interfaces).
- `.mu.js` are gitignored+regenerated in apps, git-ignored+regenerated by
  `compile:mu` in plexus-core.
- **No regression to Project Explorer** — the new service is independent; it does
  not modify `modules/project-explorer`.
- Commit only when asked.

## Decisions (locked)
1. **Location:** new module `packages/plexus-core/src/renderer/modules/todl-solutions-development/`.
2. **Engine access:** relax the floor — add `@pragmatic-tech-ai/todl` to
   `plexus-core` deps; import the engine directly (no `ISolutionEngine` seam).
3. **Tree model:** the service owns its own tree (`OpenSolution` → member
   `ProjectNode` file trees), parity with `OpenProject`/`ProjectNode`.
4. **First slice:** tree + full lifecycle (New/Open solution, Add/Remove member,
   open member file). `Compose` diagnostics surfaced as `Status`; deep
   Problems-dock integration deferred.
5. **devUI:** replace its existing solution module with the new one.

## The TODL engine we build on (already shipped)
- `SolutionManagerService` — `NewSolution(loc)` / `OpenSolution(loc)` / `Save()` /
  `SaveAs(loc)` / `CloseSolution()`, `Compose(members: PackageRef[]) → Diagnostic[]`,
  `RecentSolutions`, `ActiveSolution → SolutionViewService`. Seams (static keys):
  `StorageRegistryKey` (`IStorageProviderRegistry.CreateStorage`),
  `ProjectFactoryRegistryKey` (`IProjectFactoryRegistry.factoryFor(typeId)`),
  `DiscardConfirmerKey` (`IDiscardConfirmer.confirmDiscard`), `PackageSourceKey`
  (`PackageSource`).
- `SolutionViewService` — `Name`, `IsDirty`, `Storage`, `Members`
  (`AddMember(path,type)` / `RemoveMember`), setting bags, `OpenMembers(storageFor,
  factoryFor)`.
- `SolutionManifest` (`todl-solution` v1) — name, members (`SolutionMemberRef
  {path,type}`), settings; `create`/`parse`/`stringify`.
- `SolutionMember` — `Ref`, `Project`, `Title`, `IsResolved`.
- `IProjectFactory` (TODL) — `openProject`/`createProject`/`saveProject` over IStorage.

### `SolutionExplorerService extends ServiceBase`
- Static `Key`; surfaced by `Capability [ ServiceKey = SolutionExplorerService ]`.
- **Owns the tree:** `get OpenSolutions(): ObservableCollection<OpenSolution>`.
  On `Open`/`New`, drive `SolutionManagerService`, then build an `OpenSolution`
  from `ActiveSolution` (its `Members`), and for each member build the member's
  `ProjectNode` file tree from the member's `IStorage` — reusing the same
  node-building the Project Explorer uses (extract the shared builder if needed).
- **Commands** (project-explorer style, `RelayCommand`): `NewSolutionCommand`,
  `OpenSolutionCommand`, `AddMemberCommand`, `RemoveMemberCommand`; plus `Status`.
- **File open:** a member file `ProjectNode` → `DocumentsContentHostService`
  (same open path as Project Explorer's `OpenPath`).
- **DI seams resolved:** `SolutionManagerService`, `FileSystemService`,
  `StorageService`, `DialogService`, `DocumentsContentHostService`.

### `OpenSolution extends MuralBase` (mirror of `OpenProject`)
- `Name`, `RootPath`, `Members: ObservableCollection<OpenProject>` (each member
  is an `OpenProject` reused verbatim → members render identically to standalone
  projects, and file-open is shared for free).
- Dirty tracking bridged to `SolutionViewService.IsDirty`.

### Seam wiring (registered by the module / app)
- **`IStorageProviderRegistry`** ← `StorageService` (already has `CreateStorage`);
  register an instance-sharing alias to `SolutionManagerService.StorageRegistryKey`.
- **`IProjectFactoryRegistry`** ← `SolutionProjectFactoryRegistry` (core) mapping a
  member `type` to a registered `IProjectFactory`.
- **`IDiscardConfirmer`** ← `DiscardConfirmer` (core, DialogService-backed).
- **`PackageSource`** ← **app-provided** (`ipc-package-source` in devUI — needs
  main-process IPC); registered to `SolutionManagerService.PackageSourceKey`.
- **Concrete `IProjectFactory`(s)** ← **app-provided** (devUI's
  `todl-package-project-factory`).

## Data flow (first slice)
1. **Open:** `OpenSolutionCommand` → pick folder (FileSystemService) →
   `SolutionManagerService.OpenSolution(loc)` → engine parses `SolutionManifest`,
   builds `SolutionViewService` + `OpenMembers`. Service builds `OpenSolution`
   (members → `OpenProject` file trees). `Compose` runs; diagnostics → `Status`.
2. **New:** `NewSolutionCommand` → name+location → `NewSolution(loc)` → empty
   `OpenSolution`.
3. **Add member:** `AddMemberCommand` → pick a project folder + type →
   `ActiveSolution.AddMember(path,type)` → append an `OpenProject` to the tree →
   `Save()`.
4. **Remove member:** `RemoveMemberCommand` → `RemoveMember` → drop the
   `OpenProject` → `Save()`.
5. **Open file:** member file node → `DocumentsContentHostService`.

## Deferred (later slices)
- Deep Problems-dock integration for `Compose` diagnostics (first slice: `Status`).
- Cross-member reference navigation / reflection views.
- Solution settings-bag UI (`SolutionSettingBag`/`SettingBagGrid`).
- Drag/move members, member reordering.

## devUI replacement
- Compose `TodlSolutionsDevelopment` in devUI's `app.mu` `.modules:`; drop the old
  `SolutionModule` capability.
- Keep + rehome the app-side seam impls: `ipc-package-source` (PackageSource),
  `todl-package-project-factory` (IProjectFactory), and the seam registration
  (now targeting the new service's expectations). Delete the superseded
  `solution-explorer-service.ts` / `solution-commands-vm.ts` / `solution.module.mu`
  / `solution.resources.mu` once the new panel renders.
- Verify: devUI typecheck (build gate) + `vitest` + `electron-vite build` green.

## Testing strategy
- Unit: `OpenSolution` construction from a fake `SolutionViewService`; the
  factory-registry + discard-confirmer seams; command wiring (New/Open/Add/Remove
  drive the engine) against a fake `SolutionManagerService`.
- Integration: open a real fixture solution (a `.todl-solution` referencing 2
  member projects) → assert tree shape (Solution → 2 members → files) and that a
  member file opens.
